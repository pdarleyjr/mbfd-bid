## Curation Choices

### Positions (`2026_positions.json`)

Generated by `seed/_generate_fixtures.ts`. Transformations applied to the 2025 CSV:

1. **Station 5 removed**: The one row with `Station = "Station #5"` (A318) is dropped.
2. **Old marine positions removed**: `XX411 / XX412 / XX413` (Fire Boat 4 + Float 4) are dropped for all shifts (9 rows total).
3. **Station 4 general-pop rename**: `XX403` renamed from "Marine Deckhand" to "Firefighter #1"; `XX404` renamed from "Marine Firefighter #1" to "Firefighter #2".
4. **Station 6 added**: Nine new rows `A611..C613` (3 per shift) with canonical 2026 names: "Firefighter FBO", "Marine Firefighter", "Post St.6".
5. **A701 Union President**: `isExcludedFromCount = true`; kept in template for completeness.
6. **XX215 vacant by design**: `isVacantByDesign = true` for `A215 / B215 / C215` (Lt #2 R Float 2).

### Credentials (`reference_credentials.json`)

Parsed directly from the "Credentials" worksheet of the 2025 XLSX. The sheet has 57 named credentials with their FY25 point values. These are used as the reference set for seeding the `credentials` table and are unchanged for 2026 (no credential definitions changed between 2025 and 2026).

### Rule Book (`2026_rules.json`)

**Curation approach**: One entry per individual position ID (not one template expanded at runtime). Only specialty positions are included in this file. The rationale:

- **Specialty positions** (Station 2 Special Ops, Station 6 Marine, D-shift, Investigator, Division Chief, Captain 5, Float Captain) have unique credentials and points blocks — they are fully specified here.
- **General population positions** (Stations 1, 3, 4 — all Captains, Lieutenants, FFs on Engine/Ladder/Rescue/Float) use rank-seniority only with no points preference. Per `2026_Rules_and_Points.md` section 5, these positions require only rank-match + Paramedic (for Rescue track) and have no points preference items.

**Positions that need rule clarification** (no rule entry exists; seed script will log a warning and skip them):

- All general-population positions: Stations 1, 3, 4 Captains/Lieutenants/FFs/FFs on Engine, Ladder, Rescue, Float apparatus.
  - Per `2026_Rules_and_Points.md` §5: "Required: appropriate Rank + Paramedic (for Rescue track). Points: none — rank seniority only."
  - These have `pointsPreference: { max: 0, items: [] }` — the seed script generates them programmatically from the positions fixture, not from this rules fixture.
- Rescue Float Pool positions (XX601–XX606): No explicit rule block in `2026_Rules_and_Points.md`. Placeholder entries needed — admin to clarify.

**Known placeholder positions** (seeded with `pointsPreference: { max: 0, items: [] }`):

All positions **not listed** in this file. The seed script (`seed/2026.ts`) generates a default rule entry for every position in `2026_positions.json` that has no explicit entry in `2026_rules.json`, using:
- `requiredCriteria.rank = [position.rankRequired]`
- `requiredCriteria.credentials = []` + `custom = []`
- `pointsPreference = { max: 0, items: [] }`
- `tieBreakChain = ['points', 'rsc_seniority', 'rank_seniority']`

Admin should review and update these placeholders before running the live bid.

## Regeneration

To regenerate `2026_positions.json` and `reference_credentials.json` from the source files:

```bash
pnpm --filter @mbfd/worker exec tsx seed/_generate_fixtures.ts
```

The `2026_rules.json` file is hand-curated and should NOT be regenerated automatically.
