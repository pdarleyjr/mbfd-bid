# MBFD Bid v2 decisions

| ID | Decision | Rationale | Status |
| --- | --- | --- | --- |
| DEC-001 | Work on `feat/mbfd-bid-v2`, never directly on `main`. | Existing `main` push automation can deploy staging and apply migrations. | Adopted |
| DEC-002 | Make the repository private. | The directive treats a public personnel/certification repository as a critical privacy gate. | Implemented and verified |
| DEC-003 | Treat Media Control and all shared/unknown infrastructure as immutable. | Active operational system on a shared host. | Adopted |
| DEC-004 | Preserve unresolved policy as explicit blockers/configuration gaps. | Deterministic behavior cannot be guessed. | Adopted |
| DEC-005 | Keep AI optional, non-mutating, and absent from the initial implementation slice. | Current source retired AI; reliability and policy correctness take priority. | Adopted |
| DEC-006 | Fix reconnect correctness before adding feature surface. | A false pending pick violates canonical-live-mutation guarantees. | Implemented and locally verified; authenticated operational acceptance remains separate |
| DEC-007 | Do not deploy from the current production manifest. | Production binding placeholders and topology/CI gates are unresolved. | Adopted |
| DEC-008 | Apply supported non-major Hono, Next, NanoID, PostCSS, and ws security updates on the isolated branch. | The supported update path now uses Next 15.5.24 and OpenNext 1.20.4 without a broad framework migration. Exact-head audit has one unpatched transitive `extract-zip` high advisory. | Implemented for staging; do not suppress the remaining advisory or promote production without a supported remediation or formal risk decision |
| DEC-009 | Repair the D1 backup temporary-directory preflight before any backup invocation. | A fresh staging bookmark/export plus disposable managed migration/import/restore proof verifies the scoped procedure without rolling staging backward. | Implemented and staging-verified; disposable artifacts deleted |
| DEC-010 | Fail closed for non-mock Bid starts until all readiness facts have verified Worker providers. | The directive prohibits starting a live bid with missing, blocking, or ambiguous readiness information; the existing route supplied none. | Implemented locally; not a substitute for snapshots or a canonical DO command path |
| DEC-011 | Prove D1 recovery only with a disposable Bid-only database. | Time Travel restore is destructive to its target. A staging export/import, schema/count/foreign-key comparison, disposable managed-migration exercise, and disposable restoration establish the procedure without rolling staging backward. | Implemented and staging-derived remote proof passed |
| DEC-012 | Represent V2 staffing source A/R-day independently from legacy Bid A-Day. | The two terms have different, unconfirmed semantics. Conflating them could corrupt a staffing import or policy evaluation. | Implemented in the staging migration ledger through 0022 |
| DEC-013 | Store only keyed opaque personnel-match references in staged import rows. | Plain identifier hashes are lookup-prone. Raw TeleStaff/personnel data and HMAC keys remain outside repository and D1 source records. | Implemented in the staging migration ledger through 0022 |
| DEC-014 | Do not enable GitHub Code Scanning implicitly. | CodeQL's workflow permission is present, but GitHub rejected uploads because repository code scanning is disabled. Enabling it may require an account/policy decision. | Pending authorized repository-settings action |
| DEC-015 | Establish canonical-command semantics first through a rehearsal-only Durable Object proof. | The live mutation routes and cross-store audit behavior are unsafe to refactor speculatively. The mock path verifies typed actor construction, expected sequence, DO-local receipt idempotency, and transactional state persistence without widening live authority. | Implemented and deployed as mock-only foundation; it is not authorization for a non-mock live command path |
| DEC-016 | Use OpenNext/Workers for the existing Next 15 staging application. | Exact Next 15.5.24/OpenNext 1.20.4 artifact passed a clean Linux build, disposable canary, and staging custom-domain deployment. Windows-native `sharp` bundling remains a local development limitation. | Adopted for staging; production remains separately gated |
| DEC-017 | Revise migration 0021 in place around canonical slots, contextual source mappings, immutable observations, and generic authoritative-assignment provenance. | A source/export version, source A/R Day, or global alias cannot be the identity of an MBFD-authorized slot. The staging migration ledger now contains the corrected migration set through 0022. | Implemented and staging-verified; staffing policy/import work remains blocked |
| DEC-018 | Treat each `stable_slot_key` as one explicit authorized seat and reject overlapping planned/active authority for that slot. | A capacity pool cannot safely be inferred from staffing exports or concurrent occupants. Pool or multi-seat opportunities require an explicit future model. | Implemented locally; opportunity/capacity policy remains blocked |
| DEC-019 | Make source-import approval a one-way evidence boundary. | A mutable manifest, reviewed row, mapping, approval actor, or SQLite conflict-replacement path could silently change what a human approved. Imports now start staged, follow explicit lifecycle edges, and freeze final evidence before commit. | Implemented locally; parser/reviewer service remains unimplemented |
| DEC-020 | Require a matching immutable observation only for `TELESTAFF_IMPORT` authoritative assignments. | Source evidence must be traceable without preventing future bid awards, transfers, promotions, vacancies, or corrections before TeleStaff reflects them. | Implemented locally; authoritative reconciliation service remains unimplemented |
| DEC-021 | Treat a materialized `TELESTAFF_IMPORT` assignment as append-only source lineage. | Deletion, retyping, provenance rewrite, or SQLite `REPLACE` could silently sever an immutable observation from the authoritative record. A terminal status or bounded end date is permitted; corrections must supersede through a new record. | Implemented locally; reconciliation service remains unimplemented |
| DEC-022 | Canonicalize non-null source digests and effective dates at the database boundary. | Length-only or binary identifiers and lexical date comparisons permit malformed evidence and unstable effective-range behavior. Source provenance values use text-only lowercase hexadecimal encoding; source versions reject surrounding common whitespace; operational effective dates use valid ISO calendar form. | Implemented locally; source-effective-time compatibility policy remains blocked |
